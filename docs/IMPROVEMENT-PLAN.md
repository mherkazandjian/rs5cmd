# rs5cmd improvement plan

## Executive summary

rs5cmd is a feature-complete, largely upstream-faithful port: 19 subcommands, 128 passing unit tests, ~58 MinIO-gated e2e tests, plus opt-in `--fast` (io_uring) and `mount` (FUSE) surfaces. The core transfer engine is sound, but review turned up a cluster of **silent no-ops and silent drops** on the default SDK path: `rm --dry-run` on a prefix prints nothing (dropped future, flagged by clippy), listing errors in `rm`/`rb --force` are swallowed with exit 0, and `--retry-count` / `--no-sign-request` never reach the client. A second theme is **data-safety gaps upstream does not have or has worse**: no same-file guard on `cp`/`mv`, in-place preallocated downloads that leave full-size corrupt files `sync` trusts, no 10,000-part cap on uploads, no ETag pinning across ranged GETs. Third, the **fast path** has a real correctness bug (SigV4 double-encoding + raw keys → wrong key or 403 for `%`, space, `?`) behind an otherwise good performance story. Fourth, **there is no CI gate at all**: the tree fails `cargo fmt --check` (135 hunks), carries 8 clippy warnings (one the F01 bug), and release.yml builds untested commits. Mount and fast-path tests only run under docker compose. Most high-impact items are one-to-fifty-line fixes; the few medium ones (atomic downloads, cancellation, mount inode lifecycle) are well scoped.

## Additions from the completeness pass (verified against source)

- **C1 `cp`/`mv` swallow listing errors and exit 0** (same class as F19). `src/command/cp.rs:374-379` prints every listing error and `continue`s without setting `had_error`, and nothing checks for an empty pair set. `cp s3://b/nomatch/* /tmp/` prints "no object found" and exits 0; a mid-pagination AccessDenied yields a partial copy with exit 0 (upstream exits 1). Fix: fatal errors (NoObjectFound, AccessDenied, NoSuchBucket) set `had_error` and bail on empty expansion; keep the #749 `continue` only for per-entry local errors. Reword F24 so sync does not "mirror cp" as-is. Small, high impact.
- **C2 Path traversal on download.** `cp.rs:390-391` does `dst.join(&rel)`; `Url::join` -> `path_join` -> `clean_path` (`src/storage/url.rs:403-440`) collapses `..`, so a remote key `p/../../etc/x` under `cp s3://b/p/* /out/` resolves to `/etc/x`. Same in sync's `generate_destination_url`. Reject relative paths containing a `..` component with `op_error` in `expand_sources` and sync; unit test on `Url::join`. Small, high impact (data-safety).
- **C3 Bucket-region auto-detection (#858) absent.** `S3::new` ignores the URL; region comes only from `--region`, profile, or the `us-east-1` fallback (`s3.rs:619-622`). On real AWS a bucket in another region fails with 301/AuthorizationHeaderMalformed instead of upstream's GetBucketRegion fallback. docs/UPSTREAM-INTEGRATION.md records it as deliberately skipped, but it is the most common real-AWS failure mode. Proposal: HeadBucket `x-amz-bucket-region` on 301 + rebuild client, cached per bucket, no-op under `--endpoint-url`; pairs with F09. Medium.
- **C4 `sync` treats dest-client build errors and any "not found"-ish message as an empty destination.** `sync.rs:571-574` returns an empty map on `new_client` failure; `sync.rs:579-582` string-matches `not found`, which also matches unrelated errors (missing profile or CA file). Result: everything re-uploads as "only in source" and `--delete` deletes nothing, silently. Propagate the client error and downcast `NoObjectFound` (`storage/mod.rs:24-25`) instead of substring matching. Small.
- **C5 `cat` on a local file reads the whole file into memory.** `cat.rs:67` `tokio::fs::read` then one `write_all`; a multi-GiB local cat OOMs. Use `tokio::io::copy` or the remote chunk loop at `cat.rs:62-65`. Local wildcards are also unsupported (`cat.rs:47-49`). Small.

## Top priorities (ordered by impact/effort)

### 1. `rm --dry-run` / `rb --force --dry-run` on prefixes print nothing (F01)
- **What**: dry-run branch of `delete_chunk` drops the `tx.send` future unawaited.
- **Why**: `src/storage/s3.rs:1168-1176` `let _ = tx.send(Object{..})` (clippy `let_underscore_future` at 1170); every other send in the fn is `.await`ed. `rm.rs:120-129` and `bucket.rs:73-82` print only what arrives. Comments at `bucket.rs:50-55`, `88-90` and `tests/e2e.rs:1391-1395` codify the symptom with a wrong explanation.
- **Change**: `if tx.send(Object{url:Some(u),..}).await.is_err() { return; }`; rewrite the three comments to say "dry-run multi_delete emits one line per listed object, no DeleteObjects call".
- **Effort**: small (1 line + comments).
- **Test**: e2e `rm_dry_run_lists_objects` (3 objects; one `(dry-run) rm s3://b/p/x` line each, text and `--json` `dryRun:true`; objects still listed after); strengthen `rb_force_dry_run_deletes_nothing`. Prerequisite for F26.

### 2. `rm`/`rb --force` feeders swallow listing errors and exit 0 (F19)
- **Why**: `rm.rs:107-118` and `bucket.rs:62-70` only match `obj.url`; `Object::with_error` (`storage/mod.rs:95-101`) has `url: None`, so NoObjectFound (`s3.rs:1341/1456/1600`), paginator errors (`s3.rs:1274`, also 1378/1497), AccessDenied, NoSuchBucket all vanish. `rm s3://b/typo/*` → nothing, exit 0. Local rm (`rm.rs:132-137`) and ls/du/tree already handle `err`.
- **Change**: match `obj.err` first in both feeders; feeder task returns `bool`, `had_error |= feeder.await.unwrap_or(true)`; `op_error("rm", ..)`; in `rb` bail after draining (keep `rb --force` versioned-bucket limitation at `bucket.rs:57-59` as documented). Amend `docs/UPSTREAM-INTEGRATION.md` §4 (#751 entry is inaccurate for rm/rb).
- **Effort**: small.
- **Test**: e2e `rm s3://bucket/nomatch/*` → non-zero exit + "no object found"; `rb --force` on nonexistent bucket → non-zero.

### 3. `--no-sign-request` is a no-op (F71)
- **Why**: `command/mod.rs:216` → `Options.no_sign_request` (`storage/mod.rs:159`); `S3::new` (`s3.rs:572-669`) never reads it. Fast path `cp.rs:699-717` bails "no AWS credentials found" regardless.
- **Change**: in `S3::new` after the profile branch (~s3.rs:580): `if opts.no_sign_request { loader = loader.no_credentials(); }`. Fast path: honour it (optional `Signer`) or bail with a clear message.
- **Effort**: small.
- **Test**: negative e2e (no flag, `env_remove` AWS creds → error); positive requires an anonymous-read bucket policy applied via the SDK in the test (dev image has no `mc`).

### 4. `--retry-count` is a no-op on the SDK path (F02)
- **Why**: `mod.rs:124-126` default 10 → `mod.rs:231 max_retries`; `S3::new` never calls `.retry_config(..)`; only `fastpath/runtime.rs:277-300` uses it. README.md:86 advertises classified backoff that does not exist on the default path. s3cfg override (`mod.rs:459-462`) and `run` forwarding (`run.rs:140-141`) are inert too.
- **Change**: `builder = builder.retry_config(if opts.max_retries == 0 { RetryConfig::disabled() } else { RetryConfig::adaptive().with_max_attempts(opts.max_retries.saturating_add(1)) })` + one-line comment that the flag overrides `AWS_MAX_ATTEMPTS`. Reword README.md:86-87.
- **Effort**: small (~5 lines + import).
- **Test**: tokio unit test building `S3` with `max_retries: 7`, assert `client.config().retry_config().unwrap().max_attempts() == 8`; `max_retries: 0` → disabled.

### 5. `cp`/`mv` onto itself truncates/deletes the user's file (F11)
- **Why**: `fs.rs:107 fs::copy(src, dst)` truncates first; `cp.rs:568-571` then `remove_file(src)` for mv. `resolve_single_dest` (`cp.rs:472-478`) and `url.rs:370-372/248-262` make `cp /x/a.txt /x/` and `mv dir/* dir/` yield dst == src. S3 side: `--client-copy` (`cp.rs:532-533`) or a metadata-changing server copy (`cp.rs:535`) succeeds then `cp.rs:537-539` deletes the only copy.
- **Change**: compare cleaned `absolute()` strings per pair in the expand loop (`cp.rs:388-392`) and the single-source branch (`cp.rs:365-368`): `op_error(.., "source and destination are the same")`, `had_error = true`, continue. In `Filesystem::copy` add a `#[cfg(unix)]` `(dev, ino)` check via `MetadataExt` **before** the dry-run short-circuit at `fs.rs:100-102`.
- **Effort**: small (~30-60 lines).
- **Test**: unit (copy a.txt onto itself fails, content intact); e2e `mv x.txt .` and `cp /dir /parent/`.

### 6. Uploads > 80 GiB fail late: no 10,000-part cap in `upload_parts` (F67)
- **Why**: `s3.rs:36 MAX_MULTIPART_PARTS`; `copy_parts` (1927-1934) grows part size, `upload_parts` (1052-1053) uses `self.part_size` verbatim; cp default 8 MiB (`cp.rs:44-45`); `pipe.rs:316 part_number += 1` unbounded. Shared `upload()` serves cp/sync/mv/mount.
- **Change**: extract `fn effective_part_size(size: u64, configured: u64) -> u64` from 1929-1933, call at 1052 and in `copy_parts`; in `pipe.rs` bail before spawning part 10,001 ("raise --part-size"); mention cap in `--part-size` help (`cp.rs:43`, `pipe.rs:393-394`).
- **Effort**: small (~20 lines).
- **Test**: unit: 100 GiB @ 8 MiB → 11 MiB; 5 TiB @ 8 MiB → 537 MiB; pipe part-limit bail.

### 7. Fast-path SigV4 double-encodes and sends raw keys (F38, with F40)
- **Why**: `fastpath/sign.rs:37-39` sets only `payload_checksum_kind`, leaving `PercentEncodingMode::Double` + `UriPathNormalizationMode::Enabled` (SDK sets both off for S3). `client.rs:57-59` interpolates the raw key; `client.rs:147 url.parse::<Uri>()` rejects spaces, truncates at `?`/`#`, passes `%` raw → wrong key or 403; `encode_key_path` (325-345) is used only for copy-source. `runtime.rs:307-312` then retries the deterministic build failure ~21 s per wave (F40).
- **Change**: path = `/{bucket}/{encode_key_path(key)}`; set `percent_encoding_mode = Single`, `uri_path_normalization_mode = Disabled`; add `sign_s3_at(time)` seam; make `build_request` errors non-retryable (PermanentError marker or build outside `with_retry`).
- **Effort**: small.
- **Test**: unit signing `PUT /b/dir%20x/a%2Bb%25c/./d` with fixed time asserting canonical path passes through; extend `tests/e2e_fast.rs` (`dir/name with space+plus%.txt`, `a//b`).

### 8. In-place preallocated downloads leave correct-size corrupt files that `sync` trusts (F03)
- **Why**: `s3.rs:794-809` truncate+`set_len(total)`+`write_all_at` directly into `dst`; `download_single` 824-825 likewise; no cleanup on error/SIGINT (the `tokio::select!` at `main.rs:34-49` drops the run future without cancelling). `sync_strategy.rs:50-62` (default/`--size-only`) sees matching size + fresh mtime → skipped forever; only `--checksum` would notice. Second path: 200 answer to a Range request (`s3.rs:776-778`) grows the file past `total`.
- **Change**: write to sibling `<dst>.<pid>.<seq>.rs5cmd-tmp` via `OpenOptions::create_new` (keeps umask semantics; don't promote `tempfile`), Drop guard unlinks unless committed, restore mtime on the temp, fsync, `rename`. Same for `download_single`, `fs.rs:99-109` local copy, and the fast path `runtime.rs:339-343`. Treat a 200-without-Content-Range as the whole object. Document that rename replaces a destination symlink.
- **Effort**: medium (fix is small; verification needs a fault-injection knob in `src/bin/s3stub.rs` or an in-test TCP server).
- **Test**: unit for the guard (drop-without-commit removes temp, existing dst untouched); stub-driven test failing part 2 asserts no file at `dst`.

### 9. CI gate + one-time fmt/clippy cleanup (F10, plus F57/F58)
- **Why**: `.github/workflows/` has only `release.yml` (tags only; `cargo zigbuild --release --locked` at :109/:116, no tests). fmt fails (135 hunks); 8 clippy warnings incl. F01; `mount` never built in CI; `tests/e2e_region.rs:40-59` hard-codes `http://minio:9000` + creds and does not self-skip, so bare `cargo test --all` goes red.
- **Change**: `ci.yml` on push/PR: `cargo fmt --all --check`; `cargo clippy --all-targets -- -D warnings` for default, `--features fast`, `--features mount` (Linux); `cargo test --lib --bins`; e2e job with pinned `minio/minio` service (`AWS_ENDPOINT_URL`, minioadmin) running `cargo test --all` and `--features fast` (needs `ulimit -n`); mount job non-blocking. `release.yml` `needs:` via `workflow_call`. One-time `cargo fmt --all` commit; fix the 8 clippy items (`#[allow(too_many_arguments)]` on `copy_one` is acceptable); drop `#![allow(clippy::all)]` from `e2e_region.rs:24`. Guard `e2e_region.rs` with the shared `AWS_ENDPOINT_URL||S3_ENDPOINT_URL` check, use `tempfile::tempdir()`, inherit ambient creds. Add `RS5CMD_E2E_REQUIRED=1` in compose `test*` services so `endpoint_configured()` panics instead of silently skipping.
- **Effort**: medium.
- **Test**: the CI run itself; a deliberately unformatted PR fails.

### 10. Multipart loops drain every part after the first failure (F04)
- **Why**: `s3.rs:887, 1099, 1969` `buffer_unordered(..).collect::<Vec<_>>()` then `collect::<Result<..>>()` — a permanent error on part 3 of 6400 still uploads 6397 parts before `abort_multipart_upload` (1033/1905), whose failure is discarded silently.
- **Change**: `TryStreamExt::try_collect` (futures already a dep) via one `run_parts(tasks, concurrency)` helper for the three sites (also `mount/reader.rs:157-162`); `eprintln!("warning: ...")` with bucket/key/upload_id when abort fails (existing convention at s3.rs:815). Keep abort best-effort.
- **Effort**: small.
- **Test**: unit on the helper with a failing task asserting remaining tasks are not polled; stub-driven e2e counting UploadPart calls after an injected 403.
